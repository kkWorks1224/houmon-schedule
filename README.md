# 訪問スケジュール（○○訪問看護ステーション）試作版

訪問看護ステーションの訪問予定を、スマホと PC から手早く入力・変更するための Web アプリの**試作版（モック）**です。
現場の3人（遠藤さん・のぞみん・むねと）が触りながら要望を出すことを目的にしています。医療情報を扱う本番システムとして完成したものではありません。データはすべて架空です。

公開先：https://houmon-schedule.kkworks1224.workers.dev

## 使い方

- **ログインせずにデモで試す**：予定はその端末のブラウザにだけ保存されます（ほかの端末とは同期しません）。
- **Google でログイン**：共有データベース（Cloudflare D1）に保存し、3人で同じ予定を見られます。利用登録（下記）されたアカウントのみ。

### 主な操作

| やりたいこと | 操作 |
| --- | --- |
| 予定を追加 | 空き時間の行（スマホ）／時間軸の空き（PC）を押す → 利用者を選ぶ → 保存。右下の＋、「すぐ追加」の利用者、`N` キーでも可 |
| 続けて入力 | 「保存して続けて追加」：日付・担当者はそのまま、開始時刻は直前の予定の終了時刻 |
| 文章で入力 | 「文章で入力」に「青葉さん 毎週月・木 9時から60分 遠藤さん」など。ログイン時は Workers AI、デモはこの端末内の規則で読み取り |
| 定期訪問 | 入力画面の「繰り返す」→ 曜日（複数）・毎週／隔週・開始日・終了日（任意）。直近の発生日と重なりを保存前に確認 |
| この回だけ／この回以降 | 定期訪問の回を開いて変更 →「次へ」→ 範囲を選ぶ。「この回以降」は個別変更の扱い（残す／そろえる）と影響を確認してから保存 |
| 時刻・担当者をずらす | PC の日表示：予定をドラッグ（上下＝時刻、左右＝担当者、15分単位）、下端のドラッグで所要時間。週表示：別の日・担当者の枠へドラッグ。スマホ：予定を長押ししてから上下になぞる。定期訪問の回は「この回だけ」の変更。重なるときは確認、トーストの「元に戻す」で取り消し |
| 完了・お休み | 予定カードを右にフリック＝完了、左にフリック＝お休み（定期はこの回だけ）。元に戻すボタンあり。入力画面の「状態」でも同じ操作 |
| 基本の週間予定 | 定期訪問 → 基本の週間予定 → 枠を登録 →「期間を指定して予定を作成」 |

キーボード（PC）：`N` 追加／`T` 今日／`←` `→` 移動／`D` `W` 日・週／`1`〜`4` 担当者の絞り込み／`/` 検索／`Enter` 保存／`Ctrl・⌘+Shift+Enter` 保存して続けて追加／`Esc` 閉じる

## 起動方法（ローカル）

```bash
npm install
npm run db:migrate:local
npm run dev            # http://localhost:5195
```

`http://localhost:5195/auth/dev` で開発用の管理者ログイン（`.dev.vars` に `DEV_LOGIN=1` が必要。localhost でのみ有効）。

テスト：`npm test`（業務ロジック 28 件）／型チェック：`npm run typecheck`

## 設計

### データモデル（定期ルールと各回の変更を分ける）

| テーブル | 内容 |
| --- | --- |
| `staff` | 担当者。**固定 ID**（`st_endo` など）で管理し、表示名・印（1文字）は変更可能 |
| `clients` | 利用者と標準設定（所要時間・訪問内容・担当者・開始時刻） |
| `series` | 定期訪問のルール（曜日・毎週／隔週・開始日・終了日・隔週の基準週）。**各回は保存せず、表示する期間だけ展開** |
| `visits` | 単発の予定と、定期のある回の例外（`series_id`＋`occ_date`）。例外は1回につき1行（一意制約） |
| `templates` | 基本の週間予定の枠 |
| `members` | 利用を許可する Google アカウント（メール）と権限 |

- 「この回だけ」＝その回の例外行を作る／更新する。ほかの回とルールは変わらない。
- 「この回以降」＝元のルールを前日で終了し、新しいルールを作る（最初の回からなら同じルールを更新）。以降の例外は「残す（新ルールに同じ日があれば引き継ぎ、無ければ単発へ）／そろえる（削除）」を選べ、完了済みは常に残す。すべて1トランザクションで保存。
- 隔週は基準週（`anchor`）を持ち、分割しても隔週の並びがずれない。
- 週間予定からの一括作成は、その日に同じ利用者の予定（定期の回・お休みの回・前回作成分）があれば作らない＝二重登録しない。重なりがある場合は確認なしに一部だけ保存しない。
- 重複チェックは同じ担当者の時間の重なり（終了＝次の開始は重ならない、編集中の自分は除外）。定期は今後6か月分を確認。
- 画面は表示中の週（＋前後の週を先読み）だけを取得。`visits(date, staff_id)`、`series(start_date, end_date)` に索引。年 8,000 件×数年でも全件は読まない。
- 移動時間・同行訪問は未確定のため未実装。重複判定を `shared/engine.ts` の `overlaps` に集約しているので、移動時間の余白などはここで拡張できる。

### データアクセスの分離

画面は `src/lib/repo.ts` の `Repo` だけを使います。業務ロジック（`shared/service.ts`）は保存先に依存せず、

- デモ：`LocalRepo` がブラウザ内で同じ `Service` を動かし、localStorage に保存
- ログイン時：`ApiRepo` が `/api/rpc/*` を呼び、Worker 内の `Service` が D1 に保存

という同じコードの二通りの実行になっています。別の共有データベースに替える場合も `DataSource`（`worker/d1.ts` 相当）を差し替えるだけです。

### 認証・権限

- Google OpenID Connect（ID トークンを Google の公開鍵で検証。**クライアントシークレット不要**）。メール確認済みアカウントのみ。
- サーバ側で `members` 表（＋最初の管理者 `ADMIN_EMAILS` シークレット）と照合し、登録外のアカウントは API を一切使えない。管理者は設定画面でアカウントを追加・削除。
- セッションは HttpOnly・SameSite=Lax Cookie（トークンはハッシュで保存）、状態変更リクエストは Origin 確認（CSRF 対策）、CSP 等のセキュリティヘッダ、API と AI にレート制限、AI は1人1日200回まで。
- 変更操作は `audit_log` に「誰が・いつ・何の操作か」を記録（内容は保存しない）。
- ブラウザに秘密情報は置いていません（Google の Client ID は公開前提の値）。

## 技術の選定理由

| 技術 | 理由 |
| --- | --- |
| **Cloudflare Workers + Static Assets** | 画面と API を1つの Worker で配信でき、サーバ管理が不要。無料枠で3人の利用は十分。既存アプリ（glass-tasks 等）と同じ運用手順でデプロイできる |
| **Cloudflare D1（SQLite）** | 日付・担当者で索引を張って「表示する週だけ」引ける関係データベース。batch が1トランザクションなので「この回以降」や一括作成を全部か無しかで保存できる。Worker から追加の接続設定なしで使える |
| **Workers AI（Llama 3.3 70B）** | 指定どおり Cloudflare 内で完結し、外部 AI サービスの契約や API キーが不要。JSON スキーマ指定で項目を抜き出す。日付計算など規則で確実に読める項目は規則を優先し、AI は補助に限定（誤読で定期を作らないよう「毎週」「隔週」がない文は単発扱い） |
| **Hono** | Workers 向けの軽量ルーター。Cookie・セキュリティヘッダの部品があり、コードが小さい |
| **React 19 + TypeScript** | 入力画面の状態（段階・重複確認・保存状態）が多く、宣言的に書ける。型を画面・Worker・業務ロジックで共有し、保存形式の食い違いを防ぐ |
| **Vite + @cloudflare/vite-plugin** | 1つの開発サーバで画面と Worker（D1・AI）を同時に動かせ、本番と同じ構成で確認できる |
| **Tailwind CSS v4** | デザイントークン（色・角丸・影）を CSS 変数で一元管理し、スマホ／PC の出し分けを素早く書ける |
| **Motion（旧 Framer Motion）** | フリック・シートのスワイプ・選択の移動などをばねアニメーションで実装。途中で操作しても自然に追従し、`prefers-reduced-motion` に自動対応 |
| **Zustand** | 画面状態（表示日・担当者の絞り込み）と週ごとのキャッシュを小さく管理。保存後も表示日・担当者を維持 |
| **lucide-react** | 線の細さが揃ったアイコン。SF Symbols に近い見た目 |
| **Vitest** | 定期の展開・例外・重複・二重登録防止など業務ロジックを素早くテスト |
| **Google ログインのみ（OIDC ID トークン方式）** | 指定どおり。シークレットを持たない方式なので漏えいリスクと設定作業が少ない |

### デザイン

Apple の Human Interface Guidelines の Liquid Glass の考え方に沿い、**ガラス素材はナビゲーション層（浮かぶタブバー・ツールバー・シート）だけ**に使い、予定の内容は白い不透明なカードで読みやすくしています。担当者は色に加えて名前と1文字の印、訪問内容は「看・リ・他」の文字で区別。押せる領域は 44pt 以上、空き時間は行全体が押せます。
